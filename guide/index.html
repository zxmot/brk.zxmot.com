01 / GETTING STARTED →

快速开始

放置 init.js、创建 brk.ts、配置 esbuild、写出第一个 page.vino。五步走完，一个页面能跑起来。

你拥有一个最小可运行项目
02 / PHILOSOPHY →

设计哲学

为什么没有虚拟 DOM、没有 hooks、没有调度。四条核心取舍，解释 brk 为什么能这么小。

你能判断 brk 适不适合你的场景
// 核心 写页面的日常，全在这四章
03 / JSX →

JSX 语法

cls / css / clk 三个简写，标签解析规则，children 的展开规则，以及三个最容易踩的坑。

你能一次写对 JSX
04 / PAGE CONTRACT →

页面契约

export const page = { vino } 的完整含义。为什么是 page，为什么是 vino，以及为什么约定越少越好。

你能理解 brk 与你的代码的唯一接口
05 / RENDERING →

渲染与更新

渲染一次意味着什么，以及三种更新模式：整块替换、文本更新、属性更新。什么场景用哪种。

你能为每种变化选择正确的更新粒度
06 / CONTEXT →

父子通信

用 ctx 对象替代 ref 与回调 props。父拥有接口形状，子拥有实现，ctx 就是两者之间的合约。

你能在父子组件之间传递能力与状态
// 进阶 从"一个页面"到"一个应用"
07 / MULTIPLE PAGES →

多页容器

覆盖 brk.opens，写一个带菜单与内容区的外壳。子页面状态保留的三种策略，以及 brk 语境下的"微前端"是什么。

你能组织多个页面共存
// 读完之后

你会拥有这些

  • 一个可运行的最小 brk 项目，知道每个文件的作用
  • 能独立写出一个完整页面，包括状态更新与异步加载
  • 能搭一个多页外壳，在多个子页面之间切换
  • 能判断 brk 是否适合当下项目，以及为什么
  • 知道哪些事该自己做，哪些事 brk 会替你兜底
  • 遇到 brk.* 的 API 时能猜到它大概怎么实现
// 阅读前提

开始之前，假设你已经会这些

  • 能读懂 JavaScript / TypeScript 基本语法
  • 知道 JSX 大致长什么样（或读过 React 文档）
  • 会一点 esbuild，或愿意现学三条配置
  • 理解 import() 动态加载模块是什么
