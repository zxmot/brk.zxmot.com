brk.html

一个基于 Shadow DOM 的样式作用域容器。
它不注册自定义元素，不用 customElements.define()， 也不走 <template> + cloneNode() 那套。 它只借用了 Web Component 规范中的一件事：Shadow DOM 的样式隔离。

brk.html: FunctionComponent<{ cls?, css?, clk?, ... }> // 返回一个普通的 HTMLElement（外层 div）
01 —

它解决什么问题

真实项目里总会有这样的时刻：你从外部引入了一个复杂组件（一个富文本编辑器、一个图表库、一个 UI 组件）， 它自带一堆样式，你需要给它"套一层自定义外观"，但又不想影响自己项目里其他地方的样式。

这时有两个极端选择：

· 全部写成行内样式。 完全隔离，但一段复杂组件的样式会变成几百行 css="..."，无法维护；
· 直接加 class。 干净，但只要类名撞一次，两边的样式就互相污染。

brk.html 提供第三种选择：把内容放进一个 Shadow Root 里， 在里面用正常的 CSS 写样式——外面看不见里面，里面也看不见外面。

它是一个样式隔离区，不是一个组件化方案。

它不会让代码变得"可复用"、不会带来生命周期、不会有 props 校验。它只做一件事：让 CSS 作用域互相不干扰。

02 —

最小示例

下面是一个完整的页面级组件——一个带页头、导航和内容区的应用骨架。 所有样式写在内部的 <style> 里，不会泄漏到外面。

shell.tsx 
import { brk } from '@/brk';

export const Shell = ({ name, title, menus }: any) => (
  <brk.html css="display: block; min-height: 100vh">
    <style>{`
      :host {
        --c-line: #e5e7eb;
        --max-w:  1080px;
      }
      .header {
        border-bottom: 1px solid var(--c-line);
      }
      .header .container {
        display: flex;
        align-items: center;
        justify-content: space-between;
        height: 60px;
        max-width: var(--max-w);
        margin: 0 auto;
        padding: 0 24px;
      }
      .main {
        max-width: var(--max-w);
        margin: 0 auto;
        padding: 48px 24px;
      }
      .nav a {
        margin-left: 20px;
        color: #6b7280;
        text-decoration: none;
      }
      .nav a:hover { color: #111827; }
    `}</style>

    <header cls="header">
      <div cls="container">
        <a href="/" cls="logo">{name}</a>
        <nav cls="nav">
          {menus.map((item: any) => (
            <a href={item.href}>{item.name}</a>
          ))}
        </nav>
      </div>
    </header>

    <main cls="main">
      <h1>{title}</h1>
      <div cls="placeholder"/>
    </main>
  </brk.html>
);

三点值得注意：

· 外层 <brk.html> 上可以写 cls / css / clk， 它们会作用在返回的那个外层 <div> 上；
· 内部的 <style> 是原生标签， 会被正常创建并挂到 shadow root 上，只影响这个 shadow 内部；
· :host 指向外层 div， 所以 :host { display: block } 就是给外层 div 设样式。

03 —

它在 DOM 里长什么样

brk.html 返回的是一个普通的 <div>—— 它没有什么特别之处，你可以像操作任何元素一样操作它。特别的是它内部挂着一个 Shadow Root： 

<div css="display: block">           ← brk.html 返回的元素
  #shadow-root (open)              ← 内部隔离区
    <style>...</style>               ← 你的 CSS，只在这里生效
    <header class="header">        ← 你的内容
      <div class="container">...</div>
    </header>
    <main class="main">...</main>
  #/shadow-root
</div>

这种结构和你在浏览器里直接用 attachShadow({ mode: 'open' }) 建立的结构完全一致——因为 brk 做的就是这件事。没有额外的一层、没有隐藏的机制。

mode: 'open' 意味着你在 DevTools 里能直接看到 #shadow-root 的内容， 也可以用 element.shadowRoot 在代码里访问它。

04 —

属性、:host 与样式作用域

属性处理很简单：你传给 <brk.html> 的所有属性，都会被应用到外层 <div> 上。 这与 brk 里任何其他元素的行为完全一致。

写法 效果
cls="widget" 外层 div 加上 class="widget"（注意是外部样式表的类，不受 shadow 影响）
css="display:block" 外层 div 的 style 属性
clk={handler} 外层 div 的点击事件（能捕获 shadow 内冒泡上来的点击）
id="app" 外层 div 的 id

:host 就是外层 div。这是 Shadow DOM 规范里定义的行为—— brk 严格遵守它，没有做任何改变。所以在内部的 <style> 里：

shadow 内的 <style> 
/* 作用在外层 div 上 */
:host {
  display: block;
  --brand: #5eead4;          /* CSS 变量可以透给内部 */
}

/* 只在 host 处于某个状态时生效 */
:host([data-open]) {
  transform: scale(1.02);
}

/* 内部元素 —— 外部同名 class 影响不到它 */
.header {
  border-bottom: 1px solid var(--brand);
}
!

:root 在 shadow 里不生效。 因为 :root 指的是 <html>， 而 shadow 里的内容不在 <html> 的直接命名空间里。 用 :host 代替。

05 —

三条约束

Shadow DOM 的隔离是双向的。这一点在带来好处的同时，也带来三条需要注意的约束。

1. 外部全局样式进不来。 init.css 里定义的类、内置组件的样式、 任何"宿主的全局样式"——都不会影响 shadow 内部。 内部必须有自己完整的样式定义。

2. 不要在内部使用 brk.card 之类的全局组件。 它在外部是有样式的（来自全局 CSS），到了 shadow 里就"没皮肤"了—— 它依然会渲染成一个 div，但视觉上和外部完全不同。

3. 内部样式也出不去。 内部定义了一个 .widget 类， 外部再写 .widget 也不会冲突，但也不会共享。

×

这三点不是 brk 的限制，是 Shadow DOM 本身的性质。 brk 借用它的隔离能力，就同时接受了它的隔离边界。这是取舍的一部分，不是 bug。

06 —

关于 <style> 里的 CSS

brk 不提供 CSS 的处理能力——它不解析 CSS、不解析 @import、 不帮你把 .css 文件转成字符串。它只接受一个字符串作为 <style> 的内容。

这个字符串从哪里来，完全由你决定。常见几种做法：

做法 说明
内联模板字符串 直接在 style 标签里写 `...`，适合样式少、且只此一处的情况
esbuild 文本加载 配置 loader: { '.css': 'text' } 后 import css from './view.css' 得到字符串
独立 .css.txt 如果 .css 有别的 loader 占用，用 .css.txt 后缀避开冲突
运行时拼接 从主题变量拼接字符串，用于动态主题场景
//

构建配置是你的自由。 brk 不关心你的 .css 怎么加载进来， 只关心它最终是不是一个字符串。

07 —

它与 Web Component 的关系

brk.html 借用了 Web Component 规范中的一部分——Shadow DOM 的样式隔离。 但它没有借用其他部分：

// Web Component 完整规范

  • 调用 customElements.define() 注册标签
  • 使用 <template> + cloneNode() 定义结构
  • 拥有 connectedCallback / disconnectedCallback 等生命周期
  • 需要 observedAttributes 处理属性变化
  • 有一套完整的"自定义元素"心智模型

// brk.html

  • 不注册任何标签，只是一个函数
  • 不用 template，直接用 JSX 生成
  • 没有生命周期——普通 vino 一次渲染
  • 属性就是外层 div 的属性，没有 observed 机制
  • 只借用 Shadow DOM，不涉及自定义元素

brk.html 不是"用 brk 写 Web Component"。

它是"借用 Web Component 里唯一真正需要的那一块——样式隔离"。

这个取舍的结果是：不需要为组件命名、不需要考虑注册时机、不需要担心命名冲突。 一个 brk.html 就是一个函数调用， 和 brk 里任何其他组件完全一样。

08 —

什么时候用它，什么时候不用

// 适合

  • 引入外部复杂组件，需要自定义外观
  • 写一个独立的、样式不依赖全局的 UI 模块
  • 需要一个"内嵌 widget"，不希望被页面样式影响
  • 样式复杂到行内写法不可维护，又不想污染全局

// 不适合

  • 普通的页面组件——直接用函数就行
  • 需要用到 brk.card 等全局组件的场景
  • 需要复用全局 CSS 变量和工具类的场景
  • 想"用 Web Component 写组件"——这不是它的目的

判断标准很简单：如果你需要"和外部的样式打架"，就用它；如果外部样式本来就是你想用的，就别用。
