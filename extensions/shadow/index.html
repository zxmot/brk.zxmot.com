brk.html

一个容器组件。放进去的内容，样式和外面互不干扰。
当你想给一块界面单独一套 CSS，又不想被页面上其他样式影响到时，用它。

01 —

这是什么

brk.html 是一个函数组件，和 brk.card 在用法上没有区别——都是 <brk.html>...</brk.html> 这样用。

它和普通组件的唯一区别是：它会给内容划一个独立的样式作用域。 你在它的 styles 属性里写的 CSS， 只会作用于它内部；外面页面上写的 CSS，进不到它内部来。

一段 CSS，一个作用域。

写完就封闭，不影响别人，也不被别人影响。

它的做法借鉴了 Web Component 的思想——把样式关进一个作用域里。 但它没有走到"注册一个自定义元素"那一步：不占用任何全局标签名， 不需要先注册再用，也不会和其他库产生冲突。它就是一个普通组件， 只是返回的容器带上了样式隔离能力。

02 —

为什么需要它

平时写页面，CSS 是全局的。这带来一个反复出现的问题： 当你引入一段来自别处的界面时，它的样式和页面上的样式会互相污染。

典型场景有三种：

01 / THIRD-PARTY

引入外部组件，想改它的样式

从别处拷来一个复杂的组件，它的 CSS 和你的页面样式打架。 要么改它的源码，要么用 !important 强行覆盖。

02 / CONFLICT

同一个页面里两块界面互相干扰

页面有两块区域，各自有 .btn、.title 这样的类名。它们本来是独立的， 但因为 CSS 是全局的，谁后加载谁生效。

03 / SELF-CONTAINED

一个模块想自带样式

这个模块要放到别人的页面里用。希望它自己带样式， 不希望使用者额外引一份 CSS，也不希望它的样式漏出去影响别人。

这三种场景的传统解法都不太理想：

· 写行内样式——遇到伪类、媒体查询、多元素组合就写不了；
· 加长前缀（user-card__btn）——要处处记得加，一漏就失效；
· 用 CSS-in-JS 方案——引入运行时，体积和心智成本都涨。

brk.html 提供了第四条路：把样式写进一个封闭的作用域里。

03 —

怎么用

传入两个东西：一段 CSS 字符串（styles），和任意子元素（children）。 组件返回一个 HTMLElement，和普通组件一样。

demo-app.tsx 
import { brk } from '@/brk';

const DemoApp = ({ name, title, menus }) => (
  <brk.html styles=\`
:host {
  --c-line:  #e5e7eb;
  --max-w:   1080px;
}
.header {
  border-bottom: 1px solid var(--c-line);
}
.header .container {
  display: flex;
  align-items: center;
  justify-content: space-between;
  height: 60px;
}
.main {
  max-width: var(--max-w);
  margin: 0 auto;
  padding: 48px 24px;
}
\`>
    <header cls="header">
      <div cls="container">
        <a href="/" cls="logo">{name}</a>
        <nav cls="nav">
          {menus.map(item => (
            <a href={item.href}>{item.name}</a>
          ))}
        </nav>
      </div>
    </header>

    <main cls="main">
      <h1>{title}</h1>
    </main>
  </brk.html>
);

几点说明：

· styles 里写的就是普通 CSS， 唯一区别是根选择器用 :host 而不是 :root；
· children 里用 cls 指定类名， 和页面里的用法完全一致；
· CSS 变量天然穿透——定义在 :host 上的 --xxx，可以被内部所有元素使用，也可以被外部页面覆盖。

04 —

它的边界在哪里

理解 brk.html 最重要的一点，是搞清楚 什么东西能穿过这个边界，什么东西不能。

样式进入
styles 里写的 CSS ✓ 作用于内部
外部页面的 CSS ✕ 无法命中内部元素
外部 CSS 里的 :root、* 等选择器也不会命中内部
样式溢出
内部 styles 里写的 CSS ✓ 只影响内部
不会泄露到页面其他部分——不存在"写了一个 * 把整页都改了"的情况
变量穿透
:host 上定义的 --xxx ✓ 外部可以覆盖
内部元素 var(--xxx) ✓ 会读到外部传入的值
这是唯一的、有意保留的通道

这三行可以概括成一句话： 样式进不去也出不来，只有 CSS 变量是双向通道。

这个设计是有意的——它让 brk.html 既能做到彻底的样式隔离，又保留了"外部可以调主题色"的能力。 比如你在页面上设置 --primary: red， 内部的按钮如果引用了 var(--primary)， 就会跟着变红。

05 —

什么时候用它

它不是一个"更高级的组件"。绝大多数情况下，普通组件就够了。 用它的判断标准很简单：你需不需要一个独立的样式作用域？

// 适合

  • 引入了一段来自别处的复杂组件，需要给它改样式
  • 页面里两块独立的界面，样式互相打架
  • 要封装一个"自带样式"的模块给别人用
  • 页面组件写多了，需要一块"不会被污染"的干净区域

// 不需要

  • 普通的内容块、卡片、列表——用 brk.card 或普通 div
  • 样式本来就简单，两三个类名就能解决
  • 页面里所有内容共享一套设计系统，不需要隔离
  • 需要让外部 CSS 频繁微调内部细节——隔离反而成为阻碍
//

一条经验： 当"样式冲突"成为你的主要问题时，用 brk.html； 当"样式复用"是你的主要需求时，别用。前者是为了隔绝，后者是为了共享。

06 —

几个注意点

1. 根选择器用 :host，不是 :root。
:root 指的是文档的根元素， :host 指的是这个 shadow 容器的宿主元素。 在 brk.html 里写 :root 不会报错， 但也不会有任何效果。

2. 外部 CSS 里的选择器无法命中内部元素。
哪怕你在全局 CSS 里写了 .header { ... }， shadow 里的 .header 也不会受影响。 这是隔离的代价，也是隔离的意义。

3. 每个 brk.html 都是一个独立作用域。
页面上有 N 个 brk.html，就有 N 个互不干扰的样式空间。 这也意味着你无法"在 A 里定义一次，让 B 也生效"——需要共享的样式， 应该提到两者之外，或者用 CSS 变量传进去。

4. 事件照常冒泡。
shadow 内部的 DOM 事件（点击、输入等）会照常冒泡到外部， 在 shadow 之外的父元素上用 addEventListener 也能收到。这一点和普通组件完全一致。
